# Web Components Devkit 1.0.0-rc13 — Release Notes

**Released:** 2026-11-12 · **Pre-release** (`npm install @keenmate/web-components-devkit@rc`)

These notes cover the changes since **1.0.0-rc12**, the last version on npm. They are the
devkit's first release notes; earlier versions are recorded in the CHANGELOG only.

This release wires the rulebook's release-notes convention into `kmwc doctor` and the
`kmwc new` scaffold, brings the scaffold's `/publish` in line with the rulebook spec, and moves
the scaffold's dark mode onto core's theme model. The Vite preset, the examples kit and the
Playwright preset are unchanged; what changes for an existing component repo is what doctor
reports.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/web-components/blob/prod/CHANGELOG.md) (section
1.0.0-rc13); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Existing component and library repos**

- [ ] Before your next publish, add `release-notes/<version>.md`, list `"release-notes"` in
      `package.json` `files`, and open your newest What's New section with the
      "Upgrade guide:" line. Doctor now fails C-RN-1 / C-RN-8 / C-RN-9 without them.
      ([details](#doctor-runs-the-release-notes-suite))
- [ ] Bring the `[canonical]` sections of `.claude/commands/publish.md` in line with the
      rulebook's `publish-command.md` (C-PC-12); `templates/new/.claude/commands/publish.md` is
      a correct copy to take them from. ([details](#the-scaffolds-publish-follows-the-spec))
- [ ] Optional: replace `:host-context()` dark-mode rules with the `data-context-theme` /
      `data-theme` block (C-CS-3 / C-CS-11). ([details](#dark-mode-follows-cores-theme-model))

**New components (`kmwc new`)**

- [ ] Nothing required: the scaffold already ships the first release notes, the spec's
      `/publish` and the new dark-mode block, so doctor is green from the first run.

## Behaviour changes

### Doctor runs the release-notes suite

`kmwc doctor` adds the rulebook's `release-notes` suite to the suites it runs, for every
published package (components and libraries; in a monorepo, each `kmwc.packages` entry). Its
FAILs are doctor errors like any other rulebook suite's. A repo that hasn't adopted the
convention gets C-RN-1 ("no release-notes/ folder") until the notes for its next publish exist.
The suite checks that every published version since adoption has notes, the file names and
headers, the canonical sections and their order, the Contents anchors, the checklist task boxes,
that `files` ships the folder, and that every What's New section links its notes.
`--no-rulebook` still skips all suites.

## New features — scaffold

### `kmwc new` scaffolds the first release notes

A new component starts with `release-notes/0.1.0.md`, written from the rulebook template. The
template file is `templates/new/release-notes/__VERSION__.md`, named like `__FEATURE__`.
`"release-notes"` is in `files`, and the README's What's New opens with the upgrade-guide line.
`kmwc new --minimal` gets its own, shorter text.

### The scaffold's `/publish` follows the spec

The `[canonical]` sections now carry the spec's text rather than web-multiselect's, including
the release-notes steps. Step 1 drafts the notes (a patch with only Fixed / Internal entries
may skip them), Step 4 keeps the upgrade-guide links, Step 5 validates them, Step 9 ships
`release-notes/` and Step 10 stages it. The "Or `make publish`." line wasn't in the spec, so it
moved out of the Report's canonical text into an extra bullet after it.

### Dark mode follows core's theme model

`dark-mode.css` is the rulebook's canonical block:

| Was | Now |
|---|---|
| `:host-context([data-theme="dark"])`, `[data-bs-theme]`, `.dark` / `.light` | `:host([data-context-theme="dark"\|"light"])`, which core mirrors from the page or a `theme-source` |
| (none) | `:host([data-theme="dark"\|"light"])` per instance, declared last so it wins |

`:host-context()` doesn't work in Firefox and only partly in Safari. A `theme-source` that
isn't an ancestor can only reach the component through `data-context-theme`. The scaffolded
dark-mode spec tests both cases, plus a `data-theme="light"` instance on a dark page.
`docs/theming.md` describes the signals core reads.
