# Web Components Devkit 1.0.0-rc14 — Release Notes

**Released:** 2026-11-13 · **Pre-release** (`npm install @keenmate/web-components-devkit@rc`)

These notes cover the changes since **1.0.0-rc13**, the last version on npm.

This release is about the example pages on a phone and about code: API tables stack into
cards, code blocks are syntax-highlighted at build time, and long code and tables scroll
without hiding the Copy button or the last row. The CLI, doctor, the Vite preset's options and
the Playwright preset are unchanged.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/Keenmate/web-components/blob/prod/CHANGELOG.md) (section
1.0.0-rc14); this document is the upgrade guide and the highlights.

## Behaviour changes

### Reference tables stack into cards on a phone

Below 768 px every row of a `.reference-table` is a card: the first cell is its title, every
other cell sits under a small label with its column's header. Before, the table scrolled
sideways inside its card, and a long name squeezed the prose columns to a couple of words per
line. API tables are read one row at a time, so cards read better there.

| Table | Below 768 px |
|---|---|
| `.reference-table` | stacks (was: sideways scroll) |
| `.reference-table.table-scroll` | sideways scroll, as before |
| any table with `.table-stack` | stacks |
| any other table | sideways scroll, as before |

The kit fills each cell's `data-label` from its column's `<th>` (a `data-label` the page wrote
wins) and adds `role="table"` / `row` / `cell` / `columnheader`, because `display: block` drops
the table semantics in Safari. A page that renders a table after load calls
`attachStackedTables()` (or `mountExamplesKit()` again).

## New features — examples kit

### Highlighted code

`<kmwc-demo>` code is highlighted by Shiki when the page is composed — at build time and on
each dev request — so example pages load no highlighter. A hand-written block opts in:

```html
<div class="code-block" data-language="svelte"><pre><code>{#if isOpen}
    &lt;Modal onclose={() =&gt; (isOpen = false)} /&gt;
{/if}</code></pre></div>
```

- Languages: `html`, `js`, `ts`, `css`, `json`, `svelte`, `sh` (and their aliases); another
  one fails the page with an error naming it.
- Only a block whose code is plain escaped text is highlighted; one with markup of its own is
  left alone. A block without `data-language` stays as written — it may be an output a script
  fills.
- A block with `data-language` gets the same Copy button as a demo, unless it has a button of
  its own.
- Colours are the `--kmwc-code-*` tokens (keyword, string, function, property, type, tag,
  comment), each at least 4.5:1 on the code surface in both themes.

## New API

| Surface | What |
|---|---|
| `data-language` on `.code-block` | build-time highlighting and a Copy button |
| `.table-stack` / `.table-scroll` | stack any table on a phone / keep a reference table a grid |
| `attachStackedTables(root?)` | `/examples`: label and add roles to stacking tables rendered late |
| `STACKED_TABLE_SELECTOR`, `STACKED_TABLE_ROLES`, `COPYABLE_CODE_SELECTOR` | `/examples` constants |
| `--kmwc-code-type-color`, `--kmwc-code-tag-color`, `--kmwc-code-success-color` | new code-surface tokens |

## Visible changes without a migration

- The first-column `<code>` of a `.reference-table` doesn't wrap (`white-space: nowrap`); a
  long name widens its column.
- `<code>` in any table breaks only a word that can't fit (`overflow-wrap: break-word`, was
  `anywhere`).
- Code comment colour `#a0a8b4` (was `#8b949e`), keyword colour `#d38fe6` (was `#c678dd`): the
  old ones were 3.9:1 and 4.1:1 on the light-mode code surface.
- A code block's bottom padding is split between the frame and the scrolling `<pre>`; the
  block is the same height.

---

## Fixes

- Swiping a long code block sideways on a phone carried its Copy button away with the code.
- "Copied!" was barely readable in light mode (dark green on the dark code surface, 1.4:1).
- A phone's scrollbar covered the last row of a scrolling table and the last line of code.
- A Default column next to a long name was squeezed until `false` read `fals` / `e`.

---

## Internal

- The Vite plugin's HTML hook is async now (it loads the highlighter once). Only code that
  calls `transformIndexHtml.handler` directly needs to `await` it.
- New unit tests: highlighting leaves every playground code block's text unchanged; the
  `data-language` opt-in rules. New e2e specs: stacking at 390 px, code contrast in both themes,
  the Copy button on a scrolled block and on a `data-language` block.
