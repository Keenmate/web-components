## Shared infrastructure — `@keenmate/web-components-devkit` (read before touching examples/build files)

This repo follows the Keenmate component standard: the BlissFramework rulebook
(`C:\Git\BlissFramework\guidelines\web-components\` — structure, naming, CSS,
theming, README, CEM, publish) plus the devkit (`../web-components`, published
as `@keenmate/web-components-devkit`), which owns the example-site kit, the
Vite/Playwright configs and the deploy files. Do not re-create or patch those
locally — every local fork is how they drifted apart.

- **Never add** `examples-chapter-nav.js`, `examples-copy-link.js`,
  `examples-controls-store.js`, `examples-shared.css`, `plausible-snippet.html`
  or `scripts/check-variable-manifest.mjs`. The chapter nav, copy-link buttons,
  shared styles, theme switch, version badge and analytics are injected into
  every root `*.html` page by the Vite plugin automatically.
- **Generated — do not edit:** `Dockerfile`, `nginx.conf`, `Makefile`,
  `.dockerignore` (they start with a `GENERATED by kmwc sync` header). Change
  `package.json#kmwc` and run `npx kmwc sync`, or fix the template in the devkit.
  Repo-specific make targets go in `Makefile.local`.
- **Per-component settings** (title, tagline, CSS prefix, ports, accent colours,
  analytics id, image name, canonical origin) live **only** in `package.json#kmwc`.
- **Example page styles:** shared rules are in `@layer kmwc` and read
  `--base-*` tokens (pages support light / dark / auto via the theme switch), so
  any unlayered rule wins. Put component-only rules in `examples-local.css`.
  Re-theme with `kmwc.theme.accentColor`, never by copying CSS. If a second
  component needs a pattern, it belongs in the devkit.
- **Example pages are fragments:** no `<html>`/`<head>`/`<header>` — start with
  `<meta name="kmwc:title" content="…">`, the devkit layout adds the rest. Shared text
  goes in `partials/` via `<kmwc-include>`; show code with `<kmwc-demo>` (the live
  markup IS the snippet) — never hand-copy a demo into a `.code-block`.
- **Controls persistence:**
  `import { attachControlsPersistence } from '@keenmate/web-components-devkit/examples'`.
  **Landing page:** `renderExamplesIndex({ pages })` from the same module.
- **Found a bug in a shared helper?** Fix it in `../web-components` (so every
  component gets it), not here. Say so in your summary if you can't.
- **Never ship AI-assistant files:** `package.json` `files` must keep
  `"!**/CLAUDE.md"` and `"!**/.claude"` (a `CLAUDE.md` you add under `src/` is
  otherwise published with it).
- Before finishing: `npx kmwc doctor` must pass — it runs the devkit checks,
  checks the `npm pack` file list for dev-only files, and runs the rulebook's
  `*.checks.sh` suites.
